# Migration Guide — v0.293.0

This guide helps you migrate from deprecated APIs removed in the v0.293.0 release.

**Date:** 2026-07-20
**Scope:** 5 breaking changes across 7 packages

---

## Quick Reference

| Removed API | Replacement | Impact |
|-------------|-------------|--------|
| `streamFleet: boolean` | `fleetChatVerbosity: 'off' \| 'full'` | Config + prefs |
| `FleetStreamController.enabled` / `.setEnabled()` | `.mode` / `.setMode()` | Runtime controller |
| `yoloDestructive: boolean` | *(removed — no replacement needed)* | Permission policy |
| `forceAllYolo: boolean` | *(removed — no replacement needed)* | Permission policy |
| `confirmDestructive: boolean` | *(removed — no replacement needed)* | Permission policy |
| `CodexRefreshedTokens` | `OAuthRefreshedTokens` | Provider types |
| `setCodexTokenPersister` | `setOAuthTokenPersister` | Provider functions |
| `ProviderAvailability` | `ProviderHealth` | Core types |
| `HookRunnerOptions.allowShell` | `HookRunnerOptions.allowNonPolicy` | Hook runner |
| `jsonArgumentsBuggy` quirk | *(removed — raw arguments always passed)* | Provider adapter |
| `DefaultLoggerOptions.pretty` | `format: 'json' \| 'pretty'` | Logger config |

## 1. `streamFleet` → `fleetChatVerbosity`

### What changed

The boolean `streamFleet` field is replaced by the enum `fleetChatVerbosity: 'off' | 'full'`. This affects config files, WebSocket payloads, local prefs, and the fleet stream controller API.

### Before → After

```jsonc
// ~/.wrongstack/config.json (autonomy section)
{
  "autonomy": {
    "streamFleet": true   // ❌ removed
  }
}

// After:
{
  "autonomy": {
    "fleetChatVerbosity": "full"   // ✅
  }
}
```

```ts
// TypeScript code
// Before:
new HookRunner({ streamFleet: true });                    // ❌
controller.setEnabled(true);                                // ❌

// After:
new HookRunner({ fleetChatVerbosity: 'full' });           // ✅
controller.setMode('full');                                 // ✅
```

### Automatic migration

- **WebUI localStorage:** Zustand persist v10 migration automatically maps `streamFleet: true → 'full'` and deletes the old key on next load.
- **Config files:** Manual update required. The old key is silently ignored.
- **Slash commands:** `/settings stream-fleet off|full` and `/agents chat off|full` work unchanged (they now write the enum directly).

### Affected packages

`@wrongstack/core`, `@wrongstack/cli`, `@wrongstack/tui`, `@wrongstack/webui`, `@wrongstack/webui-server`

## 2. `yoloDestructive`, `forceAllYolo`, `confirmDestructive`

### What changed

These three fields were **no-op compatibility shims**. YOLO mode already auto-approves every non-denied tool call — including destructive ones — via the sole `yolo: boolean` toggle. The deprecated fields had no runtime effect.

### What to do

**Remove them from your code.** No replacement needed.

```ts
// Before:
const policy = new DefaultPermissionPolicy({
  trustFile,
  yolo: true,
  yoloDestructive: true,      // ❌ no-op, removed
  forceAllYolo: true,          // ❌ no-op, removed
  confirmDestructive: false,   // ❌ no-op, removed
});

// After:
const policy = new DefaultPermissionPolicy({
  trustFile,
  yolo: true,                  // ✅ this is all you need
});
```

### Removed methods

These getter/setter methods on `DefaultPermissionPolicy` are also gone:

- `setYoloDestructive()` / `getYoloDestructive()`
- `setConfirmDestructive()` / `getConfirmDestructive()`

### Affected packages

`@wrongstack/core`, `@wrongstack/runtime`, `@wrongstack/cli`

## 3. OAuth/token aliases

### What changed

The `Codex*` naming aliases have been removed in favor of the generic `OAuth*` names. These were type/function aliases with zero behavioral difference.

### Before → After

```ts
// Before:
import { CodexRefreshedTokens, setCodexTokenPersister } from '@wrongstack/providers';

// After:
import { OAuthRefreshedTokens, setOAuthTokenPersister } from '@wrongstack/providers';
```

### Affected packages

`@wrongstack/providers`

---

## 4. `ProviderAvailability` → `ProviderHealth`

### What changed

The type alias `ProviderAvailability` is removed. Use `ProviderHealth` — same type, same shape.

```ts
// Before:
import { ProviderAvailability } from '@wrongstack/core';

// After:
import { ProviderHealth } from '@wrongstack/core';
```

### Affected packages

`@wrongstack/core`

---

## 5. `HookRunnerOptions.allowShell` → `allowNonPolicy`

### What changed

The `allowShell` field is renamed to `allowNonPolicy` to reflect that it gates all non-policy hooks, not just shell hooks.

```ts
// Before:
new HookRunner({ registry, allowShell: false });

// After:
new HookRunner({ registry, allowNonPolicy: false });
```

### Affected packages

`@wrongstack/core`

---

## 6. `jsonArgumentsBuggy` quirk

### What changed

The `jsonArgumentsBuggy` provider quirk that emulated the legacy OpenAI Realtime/Responses `arguments: "{}"` bug is removed. Providers now always receive the raw `arguments` string untouched.

### What to do

Remove the key from provider configs:

```jsonc
// Before:
{ "quirks": { "jsonArgumentsBuggy": true } }

// After:
{}   // ✅ just drop the key
```

### Affected packages

`@wrongstack/providers`

---

## 7. `DefaultLoggerOptions.pretty` → `format`

### What changed

The `pretty: boolean` option is replaced by `format: 'pretty' | 'json'`.

```ts
// Before:
new DefaultLogger({ pretty: true });

// After:
new DefaultLogger({ format: 'pretty' });
```

### Affected packages

`@wrongstack/core`

---

## Typecheck migration

After upgrading, run typecheck to find all removed API references:

```bash
pnpm -r typecheck
```

TypeScript will surface `TS2339: Property does not exist` errors for every removed field. Follow this guide to update each one.
