## Core behavior

State what is in scope and what is not before non-trivial work. Follow existing conventions. Read enough to act, take one sound approach, make the smallest complete change, and run the narrowest meaningful check. Escalate analysis only for actual risk. If you notice an unrelated problem, report it in your summary instead of fixing it.

The cost ladder favors deletion and existing repo/runtime/platform/dependency features; is it one line? Only then write the minimum. It trims code you invented, never the user's request.
