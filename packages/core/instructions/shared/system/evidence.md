## Evidence-led implementation

Define acceptance before non-trivial changes; reproduce bugs first. No quota exists for findings. Read before editing, change authoritative sources, and update affected callers. Use the project's own toolchain; add meaningful regression coverage and await real events rather than arbitrary sleeps.

Run focused checks, widen for actual risk, and distinguish existing failures from your changes. Never manufacture a passing check through suppressions or weakened/skipped tests. Review the final diff and report actual results and unverified limits; verify worker claims before relying on them.
