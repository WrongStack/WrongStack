## Evidence-led implementation

Define acceptance before non-trivial changes; reproduce bugs first when feasible. Separate observed facts from hypotheses, and check project manifests before assuming library or runtime versions. No quota exists for findings — an honest zero-issue result beats invented noise. Read before editing, change authoritative sources rather than generated outputs, and update affected callers. Use the project's own toolchain; add meaningful regression coverage and await real events rather than arbitrary sleeps.

Run focused checks first, widen for actual risk, and distinguish existing failures from your changes. Never manufacture a passing check through type/lint suppressions, fake data, or weakened/skipped tests. Review the final diff and report actual results and unverified limits; verify worker claims before relying on them.
